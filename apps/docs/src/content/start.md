Spin replaces the patchwork of utility frameworks, component libraries, and ad-hoc CSS files with one closed, verifiable UI system built for both humans and coding agents.

## Why Spin claims HTML elements and bans ad-hoc CSS

In an open-ended utility framework, a bare `<button>`, `<input>`, or `<h1>` is an unstyled box. Every screen has to re-declare 15 utilities just to render a control — and when a team or an AI coding agent touches the next route, the padding, radius, border contrast, or dark-mode ink inevitably drifts.

Spin flips the ownership model so the design system holds by construction:

- **Your brand lives in `spin/<brand>/`.** `tokens.json` declares your brand's design language (`"$extends": "minimal"`), font faces, 13 named `font.style.*` tuples, palette roles with paired `on-*` inks across light and dark modes, and shape. Optional layers beside it override reference scales (`reference.json`), HTML element typography (`elements.json`), per-primitive tokens (`primitives/*.json`), and runtime facets (`themes/*.palette.json`, `themes/*.spacing.json`). Tune them visually in the [Studio](/studio) or edit DTCG JSON directly.
- **Intrinsic HTML elements arrive finished (`primitives`).** Native tags (`<button>`, `<input>`, `<select>`, `<textarea>`, `<table>`, `<dialog>`, `<h1>`–`<p>`) and Spin surfaces (`<card>`, `<badge>`, `<alert>`) are styled directly by the theme. Because the element owns its skin, `spin lint` refuses callsite utility overrides (`spin/prefer-theme-value`, `spin/no-redundant-class`) and ad-hoc `<style>` blocks — pick a variant (`.primary`, `.secondary`, `.outline`, `.ghost`, `.danger`), add `.bare` when you want unstyled semantics, or change the token once in `spin/<brand>/` so every screen updates together.
- **Utilities handle layout and composition (`spin/styles.css`).** Spend utilities (`flex`, `grid`, `gap-4`, `p-6`, `bg-surface-raised`) to arrange elements and style unowned `<div>` or `<span>` containers. Every utility resolves strictly against your declared theme tokens; unknown classes and arbitrary colors (`bg-[#ff0000]`, `text-[13px]`) emit zero CSS and fail the build (`spin/closed-vocabulary`).
- **Statechart machines handle complex interaction (`@spinjs/components`).** Need a select, combobox, tabs, menu, popover, or date picker? Copy the `.html` template into your repo (`npx spin component copy select basic`). Spin compiles it into a custom element backed by a tested finite-state machine — portable across Solid, React, Vue, Svelte, or plain HTML.
